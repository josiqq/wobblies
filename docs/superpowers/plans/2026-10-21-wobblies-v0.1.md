# Wobblies v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@wobblies/core`, `@wobblies/react` and `@wobblies/react-native` 0.1.0 from a professional monorepo with a Starlight docs site, playground, Expo example, CI and automated releases.

**Architecture:** The draft engine (`~/Escritorio/avatars-generator/src/engine`) is ported verbatim first and its output is frozen into stability fixtures; the public API is then rebuilt on top of a primitive render tree (`nodes`) that the string serializer and both React adapters consume. Docs, playground and the Expo app are private workspace apps that consume the real packages.

**Tech Stack:** pnpm 11 workspaces, Turborepo 2, TypeScript 6.0, tsup 9, vitest 5, Jest 30 + jest-expo 58, Biome 2, API Extractor 7, publint, attw, size-limit 14, Changesets 3, Astro 7 + Starlight 0.42 + starlight-typedoc, Expo SDK 58.

**Spec:** `docs/superpowers/specs/2026-10-21-wobblies-design.md`

## Global Constraints

- CSS animation classes are namespaced `wobbly-root`, `wobbly-breathe`, `wobbly-eyes`, `wobbly-eye` (renamed from the draft's `av-*`).
- Visual output of a non-animated avatar must be **byte-identical** to the draft engine for the same name/mood/background (enforced by the stability fixtures from Task 2).
- Every public export carries TSDoc; `createAvatar`, `toDataUri` and both `Wobbly` components carry an `@example`.
- Conventional Commits; commit at the end of every task (more often is fine).

## Review Focus

1. **`name` is `undefined`/`null`/a number at runtime** (common in JS apps: `name={user.name}` before data loads) → no throw; treated as `String(name ?? "")`, renders the empty-name avatar. Test in Task 3 (core) and Task 5 (React).
2. **Untrusted strings in `palette` / `title`** (e.g. `bg: '"/><script>alert(1)</script>'`) → the SVG string never contains an unescaped `"`, `<` or `&` from user input. Test in Task 3.
3. **`NaN`, `Infinity` or out-of-range trait overrides** (e.g. slider bugs) → non-finite values are ignored (trait derived from the name), finite values are clamped to `[0, 0.999999]`; output never contains `NaN`. Test in Task 3.
4. **Invalid `size`** (`0`, negative, `NaN`) → core omits `width`/`height` (fluid SVG); RN falls back to its default `40`. Tests in Task 3 and Task 6.
5. **Decomposed Unicode and very long names** (`"José"` vs `"José"`, a 10 000-char name) → NFD and NFC give the same avatar; a 10 000-char name renders in < 50 ms without throwing. Test in Task 3.
